# Create a New Sub-Module

Create a new aegir-hosting sub-module for a feature area that doesn't fit in existing modules.

## Existing Sub-Modules (for context)

```
hosting → hosting_task → hosting_server → hosting_web_server
→ hosting_db_server → hosting_platform → hosting_client
→ hosting_package → hosting_site
```

## User Input Needed

Ask the user for:
1. Module name (e.g., `hosting_domain` — always `hosting_` prefix)
2. Purpose and what entities/services it will contain
3. Dependencies (which existing sub-modules it needs)

## Steps

### 1. Create Directory

```bash
mkdir -p hosting_{name}/src/Entity hosting_{name}/src/Service hosting_{name}/src/Form hosting_{name}/src/Hook
```

### 2. Create Info File

`hosting_{name}/hosting_{name}.info.yml`:
```yaml
name: 'Hosting {Name}'
type: module
description: 'Description of what this sub-module does.'
package: Hosting
core_version_requirement: ^11
dependencies:
  - hosting:hosting
  # Add other sub-module dependencies as needed:
  # - hosting:hosting_task
  # - hosting:hosting_server
```

### 3. Create Module File (required for hook discovery)

`hosting_{name}/hosting_{name}.module`:
```php
<?php

declare(strict_types=1);

/**
 * @file
 * Hosting {Name} module.
 */
```

### 4. Create Services File

`hosting_{name}/hosting_{name}.services.yml`:
```yaml
services:
  hosting_{name}.{service_name}:
    class: Drupal\hosting_{name}\Service\{ServiceClass}
    arguments:
      - '@entity_type.manager'
```

### 5. Create Permissions File

`hosting_{name}/hosting_{name}.permissions.yml`:
```yaml
administer hosting {name_plural}:
  title: 'Administer {Name Plural}'
  description: 'Create, edit and delete {name plural}.'
  restrict access: true

view hosting {name_plural}:
  title: 'View {Name Plural}'
```

### 6. Create Routing File (if module has pages)

`hosting_{name}/hosting_{name}.routing.yml`:
```yaml
# Custom routes — entity CRUD routes are auto-generated by AdminHtmlRouteProvider
hosting_{name}.task.{operation}:
  path: '/hosting/{name_plural}/{hosting_{name}}/{operation}'
  defaults:
    _form: '\Drupal\hosting_{name}\Form\{Name}{Operation}Form'
    _title: '{Operation}'
  requirements:
    _permission: 'administer hosting {name_plural}'
    hosting_{name}: \d+
```

### 7. Enable

```bash
drush pm:enable hosting_{name} -y
drush cr
```

## Module Structure Reference

```
hosting_{name}/
├── hosting_{name}.info.yml          # Module metadata
├── hosting_{name}.module            # Hook discovery (can be empty body)
├── hosting_{name}.services.yml      # Service definitions
├── hosting_{name}.permissions.yml   # Permission definitions
├── hosting_{name}.routing.yml       # Route definitions (if needed)
├── config/
│   └── install/                     # Default config
└── src/
    ├── Entity/
    │   ├── Hosting{Name}.php        # Entity class
    │   ├── Hosting{Name}ListBuilder.php
    │   └── Hosting{Name}ViewBuilder.php
    ├── Form/
    │   ├── Hosting{Name}Form.php    # CRUD form
    │   └── {Name}{Operation}Form.php # Task operation form
    ├── Hook/
    │   └── Hosting{Name}Hooks.php   # Entity lifecycle hooks
    └── Service/
        └── {Name}Manager.php        # Business logic
```

Read existing sub-modules (e.g., `hosting_platform/`) before implementing to match structure.
